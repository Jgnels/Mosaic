# Version 0.1E — Restricted Observer and Runtime Controls Test Guide

**Purpose:** prove that 0.1E upgrades the existing individuals without replacing them, renders the new read-only health/Observer interface, preserves identity through pause/save/reload/resume, and stops provider work at a user-set session limit.

**Scope:** Observer only. Version 0.1E cannot start jobs, change priorities, issue commands, or otherwise control a pawn. The provider-budget test uses Dagmay's deterministic fake provider and consumes no Google quota.

## What this build adds

- **Options → Mod Settings → Dagmay** now shows provider, storage, queue, audit, and usage health.
- Provider dispatch starts paused. Event recording and durable queueing continue while it is paused or offline.
- Session, rolling-hour, UTC-day estimated-token, and reflection-heartbeat limits can be adjusted.
- Existing individuals can be paused and resumed without changing or deleting their identity, lineage, memories, or lifecycle history.
- Future colonists are not automatically enrolled unless you turn that option on.
- Private seed facts, affect, memories, and committed reflection summaries are behind a two-step Restricted Observer confirmation.
- Hidden model chain-of-thought is never requested or displayed.

## Step 1 — Close RimWorld and make safety copies

1. Close RimWorld completely.
2. Open:

   ```text
   C:\Program Files (x86)\Steam\steamapps\common\RimWorld\Mods
   ```

3. Move the existing `Dagmay` mod folder to Downloads and rename it `Dagmay_01D1_Mod_Backup`. Do not leave a second Dagmay copy anywhere under `Mods`.
4. Open this folder in File Explorer:

   ```text
   %USERPROFILE%\AppData\LocalLow\Ludeon Studios\RimWorld by Ludeon Studios\Saves
   ```

5. Copy the latest Dagmay test-colony `.rws` file to a safe backup folder. Do not move or delete the original.
6. Also copy this entire folder to the same backup location:

   ```text
   %USERPROFILE%\AppData\LocalLow\Ludeon Studios\RimWorld by Ludeon Studios\Config\Dagmay
   ```

Those sidecars contain the continuing individuals. Do not delete them when changing mod versions.

## Step 2 — Build Version 0.1E

1. Extract the supplied 0.1E source archive.
2. Open the extracted `Dagmay` folder—the one containing `Dagmay.sln`, `README.md`, and `tools`.
3. Click File Explorer's address bar, type `powershell`, and press Enter.
4. Run:

   ```powershell
   Unblock-File .\tools\build.ps1
   Unblock-File .\tools\configure-reflection.ps1
   .\tools\build.ps1 -RimWorldPath "C:\Program Files (x86)\Steam\steamapps\common\RimWorld"
   ```

Python is optional. If it is unavailable, the script should warn that static verification was skipped and continue.

The build gate passes only when the output shows:

- Core, Providers, and RimWorld each finish with `0 Warning(s)` and `0 Error(s)`;
- `Executed 36 tests; 0 failed.`; and
- `artifacts\Dagmay-RimWorld-0.1E.zip`.

If a red error appears, stop and attach the complete PowerShell output. Do not edit the source yourself.

## Step 3 — Install exactly one copy

1. Create a new empty folder:

   ```text
   C:\Program Files (x86)\Steam\steamapps\common\RimWorld\Mods\Dagmay
   ```

2. Extract everything inside `artifacts\Dagmay-RimWorld-0.1E.zip` into that folder.
3. Confirm these files exist directly at the shown locations:

   ```text
   Mods\Dagmay\About\About.xml
   Mods\Dagmay\Assemblies\Dagmay.Core.dll
   Mods\Dagmay\Assemblies\Dagmay.Providers.dll
   Mods\Dagmay\Assemblies\Dagmay.RimWorld.dll
   ```

There must not be an extra `Package` or `Dagmay` folder between `Mods\Dagmay` and `About`.

## Step 4 — Force the first run offline

In the source PowerShell window, run:

```powershell
.\tools\configure-reflection.ps1 -Mode Offline
```

This does not erase the stored Google key unless you add `-RemoveStoredGoogleKey`. Offline mode ensures the first UI and continuity test makes no provider call.

## Step 5 — Load the colony and open Dagmay settings

1. Start RimWorld normally from Steam with your usual full mod list.
2. Confirm Dagmay is enabled exactly once and its description says Version 0.1E.
3. Load the latest **copy** of the Dagmay test colony.
4. Press `Esc`, choose **Options**, choose **Mod Settings**, and select **Dagmay**.
5. At the top, confirm:

   - the title says `Dagmay 0.1E`;
   - provider dispatch says `PAUSED`;
   - mode is `offline` and provider is `none`;
   - Identity, Experience, and Reflection storage all say `healthy`; and
   - Session usage is `0/4` unless you previously saved a different 0.1E limit.

The queue may be `0` immediately after load or become `1` when a background reflection opportunity is queued. Either is correct while offline; it must not dispatch.

If the page is missing, red, or cannot scroll, stop and send `Player.log` before continuing.

## Step 7 — Pause, save, and reload one individual

1. In the colonist list, click **Pause** beside Michael.
2. Wait about one second. Michael should change from `Active` to `Paused`.
3. Confirm Lynx and Schmidt remain `Active`.
4. Close the settings window and use **Save As** to create:

   ```text
   Dagmay_01E_Paused
   ```

5. Quit RimWorld completely.
6. Start RimWorld again from Steam and load `Dagmay_01E_Paused`.
7. Return to **Options → Mod Settings → Dagmay**.
8. Confirm Michael is still `Paused`, the provider is still offline/paused, and all three stores are healthy.
9. Unlock Restricted Observer again using both confirmation steps, inspect Michael, and confirm:

   - Individual ID is still `652879a6ba8a47598402fcaa18f86635`;
   - Lineage ID is still `2a4faeb3ea03496e867ad22f262d6e8a`;
   - lifecycle/history is still present; and
   - no replacement individual was created.

10. Click **Resume** beside Michael. Wait one second and confirm the same individual is `Active`.
11. Save As:

    ```text
    Dagmay_01E_Resumed
    ```

This gate fails if pause deletes history, changes either identifier, affects another colonist's enrollment, or does not survive save/reload.

## Step 8 — Test provider pause and the two-request session cap without Google

1. Quit RimWorld completely.
2. In the source PowerShell window, run:

   ```powershell
   .\tools\configure-reflection.ps1 -Mode Fake
   ```

3. Start RimWorld from Steam and load `Dagmay_01E_Resumed`.
4. Open **Options → Mod Settings → Dagmay**.
5. Confirm mode is `fake`, but dispatch is still `PAUSED`.
6. Use the `−` button until **Maximum requests per game session** is `2`.
7. Leave dispatch paused for at least 60 real seconds while the game runs unpaused. Session usage must remain `0/2`; local event recording may continue.
8. Uncheck **Pause provider dispatch**.
9. Let the colony run at normal speed for up to four real minutes. Dagmay should make at most two deterministic fake calls, one at a time.
10. The health page should eventually show `Session: 2/2`. When another task becomes ready, it remains queued instead of dispatching.

The fake provider is local and deterministic. It uses no API key, internet connection, or Google quota, but its valid proposals still pass the real validation and persistence path.

For optional live log watching, open a second PowerShell window and run:

```powershell
Get-Content "$env:USERPROFILE\AppData\LocalLow\Ludeon Studios\RimWorld by Ludeon Studios\Player.log" -Wait | Select-String "\[Dagmay\]"
```

Expected lines include:

```text
[Dagmay] 0.1E reflection mode=fake...
[Dagmay] 0.1E provider dispatch is paused in settings...
[Dagmay] 0.1E dispatched reflection; provider=dagmay.fake; ... session=1/2.
[Dagmay] 0.1E committed validated reflection...
[Dagmay] 0.1E dispatched reflection; provider=dagmay.fake; ... session=2/2.
[Dagmay] 0.1E session request limit reached (2/2)...
```

The final limit line appears only after another queued task becomes eligible, so `Session: 2/2` with no third dispatch is the essential result.

## Step 9 — Return offline and prove the final reload

1. In Dagmay settings, check **Pause provider dispatch** again.
2. Save As:

   ```text
   Dagmay_01E_FakeCap
   ```

3. Quit RimWorld completely.
4. In the source PowerShell window, run:

   ```powershell
   .\tools\configure-reflection.ps1 -Mode Offline
   ```

5. Restart RimWorld and load `Dagmay_01E_FakeCap`.
6. Confirm:

   - mode is `offline` and dispatch is `PAUSED`;
   - session usage reset to `0/2` because this is a new process;
   - queued work, if any, remains visible and does not dispatch;
   - all three stores remain `healthy`;
   - all three original individual and lineage IDs remain unchanged; and
   - gameplay has not paused or stuttered because of Dagmay.
