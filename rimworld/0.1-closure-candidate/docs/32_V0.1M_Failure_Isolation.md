# Dagmay 0.1M — Failure Isolation

**Status:** Implemented, Compiled, and Tested in isolation; exit criterion met using existing live evidence for gameplay/outage/shutdown behavior.

## Boundary

0.1M is release-closure test infrastructure for the frozen 0.1J.3 cognitive baseline. It does not expose fault injection in RimWorld, change provider behavior, add canonical mutations, alter reflection policy, or add any pawn-control path.

## Deterministic scenario

`FailureIsolation` exercises real Core persistence, queue, validation, audit, and deterministic provider contracts for:

- unavailable/offline transport without a fabricated provider attempt;
- invalid provider response;
- request timeout;
- rate limiting;
- provider error;
- cancellation;
- nominal provider success containing malformed structured output;
- durable retry and quarantine across reflection-store reload;
- interrupted `PendingCommit` recovery when the validated replacement is absent;
- interrupted `PendingCommit` recovery when the replacement is already applied;
- conflicting identity state during interrupted-commit recovery;
- storage checkpoint mismatch with zero automatic suffix adoption; and
- shutdown/reload while work remains pending.

Every failure case asserts that canonical identity bytes, version, `IndividualId`, `LineageId`, and affect remain unchanged. The only permitted canonical mutation is one fully revalidated absent-commit recovery; already-applied recovery is idempotent and conflicting recovery is quarantined.
