# 25 — Version 0.1I: Salience & Reflection Admission

**Status:** Candidate implementation; requires owner-local build and RimWorld verification.

## Purpose

Version 0.1H proved that queue coalescing and fair scheduling work, but routine game events still
generated reflection work faster than a bounded provider budget could drain it. Version 0.1I
separates **memory admission** from **model-reflection admission**.

A supported experience may therefore be:

1. observed and written to the factual event ledger;
2. encoded into bounded perception and subjective memory;
3. applied to deterministic affect/state;
4. retained locally without an immediate model request; and
5. admitted to reflection only after deterministic evidence thresholds are met.

This preserves life history without treating every callback as equally worthy of LLM attention.

## Initial deterministic admission rules

- Critical lifecycle events: admit immediately.
- Routine physiology episodes (critical needs, health-condition changes): retain locally first and
  admit only after multiple related source events accumulate in the same bounded episode window.
- Skill growth: retain each skill-gain memory and admit reflection after repeated growth evidence
  accumulates in the longer growth window.
- Other currently supported meaningful events: admit immediately until event-specific salience
  policies are defined.

These are engineering defaults, not psychological claims.

## Safety and provenance

Admission affects only whether provider work is queued. It never deletes or rewrites canonical
events, perceptions, or memories. Suppressing an unattempted low-evidence queue task during backlog
migration leaves its source evidence intact in canonical storage.

Attempted tasks are never silently suppressed by the backlog migration path.

## Diagnostics

Runtime logging distinguishes:

- `recorded bounded experience`
- `retained experience locally; reflection admission deferred`
- `admitted reflection work`
- `coalesced reflection work`

Queue summaries also report `AdmissionDeferredSession`.

## Verification target

A successful 0.1I RimWorld session should demonstrate:

- fewer new reflection tasks than new memories during ordinary activity;
- continued capture of routine memories;
- eventual admission when related evidence accumulates;
- immediate admission of critical lifecycle work;
- healthy identity, experience, and reflection stores;
- unchanged IndividualId and LineageId values;
- continued bounded Google dispatch and validated commits; and
- no pawn-control behavior.
