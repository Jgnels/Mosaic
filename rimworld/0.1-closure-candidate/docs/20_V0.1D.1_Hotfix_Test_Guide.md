# Version 0.1D.1 — Configuration Hotfix Test Guide

**Purpose:** prove that Steam-launched RimWorld reads Dagmay's current Windows user configuration, dispatches the selected `gemini-3.1-flash-lite` model, and preserves identity whether the provider succeeds or fails.

**Scope:** Observer only. This hotfix cannot control pawns. The 0.1D build, offline, deterministic fake, and fake-reload gates already passed; this guide repeats only the build/install checks and the bounded Google gate affected by the hotfix.

## What changed

The original 0.1D helper saved the correct setting, but a Steam process that was already running could pass an older `offline` value to RimWorld. Version 0.1D.1 reads the current Windows **User** value directly before considering the inherited process value. It also changes the default model from the unavailable tested endpoint to `gemini-3.1-flash-lite`, which appeared in the owner's successful model-list diagnostic.

This does not add model cycling. Each later fallback transport attempt must be separately budgeted and audited before automatic cycling is safe to enable.

## Step 1 — Back up and remove the old installed package

1. Close RimWorld completely.
2. Open:

   ```text
   C:\Program Files (x86)\Steam\steamapps\common\RimWorld\Mods
   ```

3. Move the existing `Dagmay` folder to Downloads and rename it `Dagmay_01D_Mod_Backup`.
4. Confirm there is no second Dagmay folder left under `Mods`.
5. Keep the existing test saves and `Config\Dagmay` data. Do **not** delete them; they contain the continuing individuals.

## Step 2 — Build Version 0.1D.1

1. Extract the source archive. Open the extracted `Dagmay` folder—the one containing `Dagmay.sln`, `README.md`, and `tools`.
2. Click File Explorer's address bar, type `powershell`, and press Enter.
3. Run:

   ```powershell
   Unblock-File .\tools\build.ps1
   Unblock-File .\tools\configure-reflection.ps1
   .\tools\build.ps1 -RimWorldPath "C:\Program Files (x86)\Steam\steamapps\common\RimWorld"
   ```

Python is optional. If Python is absent, the script may warn that static verification was skipped and continue.

The build gate passes only when the output contains:

- zero build warnings and zero build errors for Core, Providers, and RimWorld;
- `Executed 33 tests; 0 failed.`; and
- `artifacts\Dagmay-RimWorld-0.1D.1.zip`.

If a red error appears, stop and attach the complete PowerShell output. Do not edit the source yourself.

## Step 3 — Install exactly one copy

1. Create a new empty folder:

   ```text
   C:\Program Files (x86)\Steam\steamapps\common\RimWorld\Mods\Dagmay
   ```

2. Extract everything inside `artifacts\Dagmay-RimWorld-0.1D.1.zip` into that folder.
3. Confirm these files exist directly at the shown locations:

   ```text
   Mods\Dagmay\About\About.xml
   Mods\Dagmay\Assemblies\Dagmay.Core.dll
   Mods\Dagmay\Assemblies\Dagmay.Providers.dll
   Mods\Dagmay\Assemblies\Dagmay.RimWorld.dll
   ```

There must not be an extra `Package` or `Dagmay` folder between `Mods\Dagmay` and `About`.

## Step 4 — Select Google without re-entering the key

In the same source PowerShell window, run:

```powershell
.\tools\configure-reflection.ps1 -Mode Google -Model "gemini-3.1-flash-lite" -KeepExistingGoogleKey
```

If it says that no stored key exists, run this instead:

```powershell
.\tools\configure-reflection.ps1 -Mode Google -Model "gemini-3.1-flash-lite"
```

Paste the key into the hidden prompt and press Enter. Do not put the key in a command argument, chat message, screenshot, save, or log.

The key is stored as a per-user Windows environment variable, outside Dagmay source and runtime records. Windows environment variables are not an encrypted secret vault; remove the key after testing if other people use the same Windows account.

## Step 5 — Watch the one-call test

1. Start RimWorld **normally from Steam**. No special PowerShell launch is needed.
2. Confirm Dagmay is enabled exactly once and the mod description says Version 0.1D.1.
3. Load the latest copy of the Dagmay test colony.
4. Let the colony run unpaused at normal speed.
5. In a second PowerShell window, run:

   ```powershell
   Get-Content "$env:USERPROFILE\AppData\LocalLow\Ludeon Studios\RimWorld by Ludeon Studios\Player.log" -Wait | Select-String "\[Dagmay\]"
   ```

6. Confirm the watcher shows both:

   ```text
   [Dagmay] Version 0.1D.1 loaded...
   [Dagmay] 0.1D.1 reflection mode=google...
   ```

   If either line still says Version `0.1D` or mode `offline`, quit and stop the test; the old package or configuration is still active.

7. Wait up to two minutes for:

   ```text
   [Dagmay] 0.1D.1 dispatched reflection; provider=google.ai-studio; model=gemini-3.1-flash-lite; ...
   ```

8. Wait for the first result line. It will be either a `committed validated reflection` success or a `reflection attempt failed safely`/`quarantined` result.
9. Immediately save as `Dagmay_01D1_Google_1` and quit RimWorld completely. Press `Ctrl+C` in the watcher PowerShell window to stop watching.

A success commit is the desired transport/schema result. A normalized provider failure is still evidence that storage safety worked, but it does not pass the live-success gate. In either case:

- the same three `IndividualId` and `LineageId` values must remain;
- all storage systems must remain `healthy`;
- a failure must not advance the affected identity version; and
- no API key may appear in the log.

## Step 6 — Return to offline mode

Run:

```powershell
.\tools\configure-reflection.ps1 -Mode Offline
```

This leaves the key stored but prevents Dagmay calls. To remove the stored key and model too, use:

```powershell
.\tools\configure-reflection.ps1 -Mode Offline -RemoveStoredGoogleKey
```

## Step 7 — Send the evidence

Attach:

1. the complete 0.1D.1 PowerShell build output;
2. the complete `Player.log` after the Google attempt; and
3. a short note saying whether the colony stayed responsive.

Do not send the API key. This test establishes only the configuration handoff and one live structured response. It does not yet establish long-run cost, model quality, automatic model fallback, large-colony performance, dialogue, UI, cross-game transfer, or pawn agency.
