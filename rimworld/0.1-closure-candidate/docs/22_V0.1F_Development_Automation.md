# Version 0.1F — Development Automation and Local Codex Guide

**Audience:** the project owner and local implementation agents.

**Capability scope:** development tooling and reproducibility only. Version 0.1F adds no new cognition and no pawn-control behavior.

## Purpose

Version 0.1F removes the manual build/install/log-transfer loop while retaining human review at the point only a person can perform: playing RimWorld and deciding whether the result behaves and feels coherent.

The same scripts are readable and usable by the owner or an agent. Human messages explain the next action. Stable files under `artifacts` give an agent exact evidence without requiring copied terminal text.

## One-command paths

Build, run isolation tests, compile the RimWorld adapter, and package:

```powershell
.\tools\dev-loop.ps1
```

Build and safely install:

```powershell
.\tools\dev-loop.ps1 -Install
```

Build, safely install, and launch RimWorld through Steam:

```powershell
.\tools\dev-loop.ps1 -Install -Launch
```

For a non-default Steam library, add:

```powershell
-RimWorldPath "D:\SteamLibrary\steamapps\common\RimWorld"
```

`-Launch` requires `-Install`. `-Install` cannot run with `-SkipRimWorld`. A failed build stops before installation.

## Evidence produced automatically

| File | Human meaning | Agent use |
| --- | --- | --- |
| `artifacts\Dagmay-build-latest.txt` | Complete PowerShell build output | Diagnose compiler/test failures without asking for copied text |
| `artifacts\Dagmay-build-result-latest.json` | Small structured success/failure summary | Verify stages, package path, hash, and exact unverified work |
| `artifacts\Dagmay-RimWorld-0.1F.zip` | Installable mod package | Input to guarded installation |
| `artifacts\Dagmay-RimWorld-0.1F.sha256.txt` | Package integrity hash | Confirm transferred bytes |
| `artifacts\Dagmay-diagnostics-latest.txt` | Redacted current/previous RimWorld evidence | Diagnose runtime behavior and distinguish Dagmay from other-mod errors |
| `artifacts\install-backups\...zip` | Previous installed Dagmay package | Manual recovery artifact after an upgrade |

Timestamped build and diagnostic evidence is retained beneath `artifacts\build-logs` and `artifacts\diagnostics`. These files are ignored by Git.

## Installation safety contract

`tools\install.ps1`:

1. refuses to run while `RimWorldWin64` is running;
2. resolves the destination to exactly `RimWorld\Mods\Dagmay`;
3. refuses linked/reparse-point destinations;
4. extracts into a unique staging directory;
5. validates `About.xml`, the package ID, and all three required DLLs before touching the installed mod;
6. archives the previous installed mod;
7. renames the previous directory, moves the verified staging directory into place, and validates it again;
8. restores the previous directory if installation fails; and
9. never accesses RimWorld saves, the `Config\Dagmay` continuity sidecars, or the Google key.

Writing under `Program Files (x86)` may require the Windows app or PowerShell to run as administrator. An access-denied result is a failed installation, not permission to weaken path guards.

## Diagnostic collection

After testing and closing RimWorld:

```powershell
.\tools\collect-logs.ps1
```

By default it includes both `Player.log` and `Player-prev.log` when available. That matters because restarting RimWorld moves the prior test process out of `Player.log`. The report includes every `[Dagmay]` line and nearby noteworthy error/exception context. It redacts Google-style API keys, the Windows user-profile prefix, and the computer name.

The compact report can still contain colony names, pawn names, mod names, and nearby third-party error text. Review it before posting it publicly. For this private project, attach it directly to the Dagmay implementation conversation.

Use `-IncludeFullLog` only when the compact evidence is insufficient. It still applies the same redaction.

## Source packaging

For a clean source archive without compiled binaries, runtime data, diagnostics, secrets, or Git history:

```powershell
.\tools\package-source.ps1
```

This creates `artifacts\Dagmay-v0.1F-source.zip` plus a SHA-256 file.

## Human/agent boundary

The agent should perform file changes, builds, isolation tests, installation, evidence collection, log diagnosis, and documentation updates. The owner performs only:

- approval for an exact external write when Windows requests it;
- hidden credential entry through `configure-reflection.ps1` when needed;
- launching/playing the requested RimWorld scenario; and
- reporting whether the visible or subjective behavior is right.

An agent must not treat successful compilation or clean logs as proof of a good memory, personality, relationship, or autobiographical interpretation.

## 0.1F acceptance check

Before promoting the tooling to **Tested on Windows**, prove:

1. a deliberately successful run creates the transcript, JSON result, package, and hash;
2. `-Install` backs up and replaces only `Mods\Dagmay`;
3. a deliberately failed build does not alter the installed mod;
4. a deliberately invalid package is rejected before the installed mod moves;
5. a normal RimWorld launch reports Version 0.1F with all continuity stores healthy;
6. diagnostic collection captures current and previous Dagmay lines and visibly redacts a synthetic test secret; and
7. the owner can follow `START_HERE.md` without editing code.

Until that Windows check is returned, the automation is **Implemented** and statically inspected, not **Tested on Windows** or **Tested in RimWorld**.
