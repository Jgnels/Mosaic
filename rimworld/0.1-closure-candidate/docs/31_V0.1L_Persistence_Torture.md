# Dagmay 0.1L — Persistence Torture Harness

**Status:** Implemented, tested in isolation, and tested in RimWorld for the recorded two-process persistence scenario.

## Boundary

This is release-closure test infrastructure for the frozen 0.1J.3 cognitive baseline. It does not add an event type, memory rule, reflection policy, provider behavior, identity field, canonical mutation, UI disclosure, or pawn-control path.

## Deterministic scenario

`PersistenceTorture` runs six simulated save/reload cycles against the real Core persistence, memory, queue, audit, and deterministic provider contracts. It proves:

- four external identity mappings retain the same unique `IndividualId` and `LineageId` through every cycle;
- the reflection queue is non-empty at each save and survives reload;
- an unavailable/rate-limited provider leaves work durable and retryable;
- new skill and social experiences continue arriving while the provider is unavailable;
- the verified experience journal becomes exactly one record ahead of a simulated save checkpoint;
- only the checkpoint prefix is exposed before recovery;
- explicit forward adoption adds the verified suffix exactly once; and
- event IDs, deduplication keys, perception IDs, memory IDs, reflection task IDs, source-event links, audit record IDs, and provider request IDs remain nonduplicated.

The current deterministic run produces 13 experiences/memories, 12 queued reflections, six durable provider-failure audit records, one forward recovery, and 238 assertions.

## What remains live

The isolation harness cannot prove Verse `ExposeData` callback ordering, real RimWorld save serialization, process shutdown timing, Windows file locks during a game save, mod interoperability, or gameplay responsiveness by itself.

## Live RimWorld evidence — 2026-07-19

**Status:** Tested in RimWorld for the recorded normal-save/normal-shutdown scenario.

A copied colony completed repeated save, main-menu reload, process shutdown, relaunch, and reload cycles with provider dispatch paused. The two retained RimWorld process logs contain eight post-load Dagmay snapshots for one StoreId. Generation increased strictly from 165 to 178; events and memories moved together from 111 to 117; all six newly logged EventIds and MemoryIds were unique and exactly matched the persisted count increase; four pawn-to-IndividualId/LineageId mappings remained unchanged; the two-item reflection queue survived every load; provider dispatch remained zero; all three stores were healthy in every snapshot; and no Dagmay failure, corruption, mismatch, rollback, recovery, duplicate, or fatal line appeared.

This passes the 0.1L live gate for graceful save/reload and normal process shutdown. Forced process termination, deliberate file locking/corruption, and explicit mismatch injection remain 0.1M failure-isolation work.
