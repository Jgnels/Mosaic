# 24 — Version 0.1H Experience Consolidation & Queue Intelligence

**Status:** Development candidate

## Purpose

0.1H reduces redundant model calls while preserving the factual event ledger and subjective-memory history.

The key distinction is:

- **Canonical experience is never discarded by queue coalescing.**
- **Reflection work may be merged** when several routine events belong to the same short-lived episode.

## Implemented behavior

### Routine-event coalescing

For one individual:

- health-condition additions, removals, and critical-need crossings share a short physiology window;
- skill-level gains share a longer growth window;
- critical lifecycle events remain unique and highest priority; and
- unknown/non-routine event kinds remain meaningful-event work.

Merged reflection tasks retain up to 100 distinct source event IDs. The event journal and memory records remain unchanged.

### Safe backlog compaction

On load, 0.1H may compact **unattempted**, single-event routine reflection tasks from older versions into the new windowed keys. Tasks with prior provider attempts, mixed/unknown evidence, or non-routine events are preserved unchanged.

Compaction changes pending work only. It does not rewrite identity, events, memories, audit records, or provider responses.

### Fair selection

When multiple eligible tasks have the same effective priority, the queue prefers an individual other than the one most recently dispatched. Higher-priority work still wins.

### Diagnostics

Startup and session-limit logs include queue counts by priority and the number of individuals represented in the queue. The diagnostic collection script identifies its source version and warns when the latest structured build result belongs to a different Dagmay version.
