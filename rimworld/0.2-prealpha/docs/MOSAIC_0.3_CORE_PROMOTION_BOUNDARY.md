# Mosaic 0.3 Core Promotion Boundary

## Scope

This candidate promotes only three provider- and environment-independent Core boundaries:

1. compound appraisal results;
2. directed multidimensional social-meaning proposals;
3. pure Character Why projections.

It does not add an appraisal engine, social-state commit service, persistence format, RimWorld
adapter, UI, presentation, dialogue turn, planner, provider call, pawn job, or game action.

## Owner-derived requirements

- emotions may be layered and ordered rather than mutually exclusive;
- generic positive/negative wellbeing remains a fallback;
- story intensity uses a bounded 0-5 owner scale;
- immediate visible reaction and later consequence remain separate;
- relationships are directed and multidimensional;
- Why projections retain exact evidence/fact/rule provenance;
- transient UI identity is not canonical.

## Audit-derived requirements

- FAtiMA concepts are used without importing its memory, goals, or serialization authority;
- social importance is not collapsed into one scalar;
- Graphiti-style provenance and temporal facts remain first-party Mosaic data;
- Multiplayer-style observer reads cannot mutate canonical state;
- no external planner or narrative runtime gains action authority.

## Runtime disposition

These are unused Core contracts. Their initial gate is compile/contracts/firewall/reproducibility.
A RimWorld test begins only when a later milestone wires them into the adapter, persistence, UI,
presentation, dialogue, or action path.
