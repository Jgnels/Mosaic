# Version 0.1C — Beginner Test Guide

**Status:** Build, upgrade continuity, storage health, and natural-event capture passed on the owner's RimWorld 1.6.4871 installation with the full mod list. Test C, the experience-journal save/reload and deduplication check, remains required.

## What this build adds

Version 0.1C upgrades an existing 0.1B identity store without replacing its individuals. It observes a deliberately narrow set of first-person changes:

- Food, Rest, or Mood crossing a critical low threshold;
- a health condition appearing or disappearing;
- a skill level increasing; and
- a tracked colonist's death as a factual lifecycle event.

For an experienced event, Dagmay stores three linked records:

1. what the adapter observed as fact;
2. what details were available to the individual; and
3. a concise, deterministic private memory with bounded affect and importance.

The experience journal is append-only and hash-chained. A missing, altered, reordered, or save-mismatched journal enters read-only safety mode.

This build does not call Google, generate language with an AI model, observe conversations, provide a mind tab, or control pawn behavior. No API key is needed.

## Before installation

1. Close RimWorld completely.
2. Back up the dedicated Dagmay test save.
3. Preserve the existing RimWorld configuration data. Do not delete the `Dagmay` folder under RimWorld's `Config` directory; it holds the 0.1B identities being tested for continuity.
4. Move `RimWorld\Mods\Dagmay` outside the Mods folder so only one Dagmay version is installed.
5. Extract the 0.1C source into a new folder such as `C:\Dagmay-0.1C`.

## Build

Open PowerShell in the extracted inner `Dagmay` folder and run:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\tools\build.ps1 -RimWorldPath "C:\Program Files (x86)\Steam\steamapps\common\RimWorld"
```

The expected automated result is:

```text
Executed 23 tests; 0 failed.
```

The expected package is:

```text
artifacts\Dagmay-RimWorld-0.1C.zip
```

Stop and preserve the complete PowerShell output if compilation or a test fails.

## Install

Extract the package into a fresh `RimWorld\Mods\Dagmay` folder. Verify:

```text
Mods\Dagmay\About\About.xml
Mods\Dagmay\Assemblies\Dagmay.RimWorld.dll
Mods\Dagmay\Assemblies\Dagmay.Core.dll
```

## Test A — Upgrade continuity

1. Start RimWorld and confirm Dagmay is enabled.
2. Load `Dagmay_01B_Test_2`, or the last successful 0.1B test save.
3. Let the game run unpaused for at least 20 seconds.
4. Save as `Dagmay_01C_Baseline`.
5. Quit RimWorld completely.
6. Open `Player.log` and search for `[Dagmay] 0.1C`.

The usual log location is:

```text
%USERPROFILE%\AppData\LocalLow\Ludeon Studios\RimWorld by Ludeon Studios\Player.log
```

Expected results:

- `Version 0.1C loaded` appears;
- the observer-service line reports `IdentityStorage=healthy` and `ExperienceStorage=healthy`;
- existing colonists retain the exact `IndividualId` and `LineageId` recorded during 0.1B; and
- existing colonists are not enrolled as new individuals.

An upgraded 0.1B save normally begins with `Events=0; Memories=0` because Dagmay does not invent past experiences retroactively.

## Test B — Observe a real bounded event

Use only the disposable Dagmay test colony. Let normal play continue at a comfortable speed. A colony with several active colonists will usually produce one of the supported changes naturally: a skill level gain, a health condition beginning or ending, or a critical need threshold crossing.

Do not injure or deprive a valued pawn merely to force this test. It is acceptable to play for one or two in-game days at high speed and wait for an ordinary event.

When an event occurs, the log should contain a line similar to:

```text
[Dagmay] 0.1C recorded bounded experience; name=...; kind=rimworld.skill.level_gained; EventId=...; MemoryId=...
```

Supported `kind` values include:

```text
rimworld.need.critical
rimworld.health.condition_added
rimworld.health.condition_removed
rimworld.skill.level_gained
```

The log intentionally shows identifiers and event type, not the private diary text.

After at least one event:

1. Save as `Dagmay_01C_Experience_1`.
2. Quit RimWorld completely.
3. Preserve the `Player.log` line and note the event and memory IDs.

## Test C — Experience save/load

This is the only remaining step after the 2026-07-16 log review. The prior run recorded 12 experiences. If all 12 occurred before `Dagmay_01C_Experience_1` was saved, the next startup should report at least 12 events and 12 memories. If the save was made earlier, the startup counts should instead match the checkpoint that was actually saved and must be at least 1.

1. Restart RimWorld.
2. Load `Dagmay_01C_Experience_1`.
3. Let it run unpaused for at least 20 seconds.
4. Save as `Dagmay_01C_Experience_2` and quit.
5. Inspect the new log.

Expected results:

- both storage fields remain `healthy`;
- `Events` and `Memories` are at least `1`;
- loading does not re-record the same event;
- the same colonist keeps the same individual and lineage IDs; and
- other mods continue behaving normally.
