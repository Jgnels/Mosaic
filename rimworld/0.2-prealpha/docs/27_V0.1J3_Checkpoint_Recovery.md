# 27 — Version 0.1J.3 Checkpoint Recovery & Continuity Guard

**Status:** Development candidate

## Why this slice exists

A RimWorld save can legitimately be older than Dagmay's external append-only experience journal. Version 0.1J.2 correctly refused to write when the journal head did not exactly match the save checkpoint, but it offered no recovery path and therefore exposed zero memories while remaining in safety mode.

Version 0.1J.3 distinguishes a **verified forward-only mismatch** from a divergent history:

- the complete external journal hash chain must validate;
- the loaded RimWorld save's stored experience position must exist as a prefix of that journal; and
- the hash at that exact position must match the save checkpoint hash.

Only then is recovery offered.

## Safety behavior

When the external journal is ahead but the save checkpoint is a verified prefix:

1. Dagmay loads only the checkpointed prefix for ordinary/Observer inspection.
2. Experience writes remain disabled.
3. No model work is created from the unadopted suffix.
4. Restricted Observer shows an explicit continuity-recovery warning.
5. The owner must confirm **Adopt verified external experience head**.
6. Dagmay then loads the verified suffix, advances the in-memory experience checkpoint to the external head, and re-enables experience writes.
7. The owner is instructed to save immediately under a new name.

This preserves newer Dagmay experience history across an intentional RimWorld save rollback. It may therefore preserve memories of events that occurred after the loaded world save point. That discontinuity is explicit rather than silent.

If the save checkpoint is not a verified prefix, Dagmay remains read-only and offers no automatic recovery.

## Continuity boundary

Recovery never replaces `IndividualId` or `LineageId`. It does not silently invent missing history, truncate the external journal, or merge a divergent chain. It is an administrative recovery operation and requires explicit confirmation in Restricted Observer Mode.

A future release should extend the same exact checkpoint protocol to identity and reflection sidecars and record administrative recovery in a dedicated append-only repair ledger.
