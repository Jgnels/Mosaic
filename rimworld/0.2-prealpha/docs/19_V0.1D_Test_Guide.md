# Version 0.1D — Beginner Test Guide

> **Historical test record:** the owner completed the build, offline, fake-provider, and fake-reload gates in this guide. The Google endpoint failed safely and led to the 0.1D.1 configuration/model hotfix. For the current package and next test, use `20_V0.1D.1_Hotfix_Test_Guide.md`; filenames, test counts, version log lines, and the old default model below describe the original 0.1D package.

**Purpose:** prove that 0.1D preserves the 0.1C individuals, records experiences while offline, commits a deterministic validated reflection without network access, survives reload, and then makes at most one tightly observed live Google test call.

**Scope:** Observer only. This build cannot control pawns and does not depend on RimTalk. Keep your existing full mod list enabled so this remains a realistic compatibility test.

## What you will test

The test has four gates:

1. build and package 0.1D;
2. load in `offline` mode and verify that the old identities and queued work survive;
3. use `fake` mode to test the complete reflection/validation/persistence path without credits or network; and
4. only after those pass, optionally use `google` mode for one live provider request.

Do not begin the Google gate if build, offline, or fake mode shows a Dagmay error.

## Step 1 — Close RimWorld and make recoverable copies

1. Close RimWorld completely.
2. In File Explorer, paste this into the address bar:

   ```text
   %USERPROFILE%\AppData\LocalLow\Ludeon Studios\RimWorld by Ludeon Studios
   ```

3. Copy the test save from `Saves` to a clearly named backup such as `Dagmay_01C_before_01D.rws`.
4. If `Config\Dagmay` exists, copy that whole folder to Downloads as `Dagmay_01C_Data_Backup`. It contains the external identity and experience history.
5. Open the Steam RimWorld folder:

   ```text
   C:\Program Files (x86)\Steam\steamapps\common\RimWorld\Mods
   ```

6. Move the existing `Dagmay` mod folder out of `Mods` and into Downloads as `Dagmay_01C_Mod_Backup`. Do not leave two Dagmay folders under `Mods`.

These are copies for recovery; do not delete your original save or data.

## Step 2 — Build 0.1D

1. Extract the 0.1D source archive to a normal folder such as:

   ```text
   C:\Users\jgnel\Downloads\Dagmay_v0.1D_Reflection_Provider\Dagmay
   ```

2. Open that `Dagmay` folder in File Explorer.
3. Click the address bar, type `powershell`, and press Enter.
4. Run these two one-time unblock commands:

   ```powershell
   Unblock-File .\tools\build.ps1
   Unblock-File .\tools\configure-reflection.ps1
   ```

5. Run the build:

   ```powershell
   .\tools\build.ps1 -RimWorldPath "C:\Program Files (x86)\Steam\steamapps\common\RimWorld"
   ```

Python is optional. If it is absent, the script should warn that static verification was skipped and continue. Do not install Python just for this test.

The build gate passes only if all of the following appear:

- Core build succeeded with 0 warnings and 0 errors;
- Providers build succeeded with 0 warnings and 0 errors;
- `Executed 32 tests; 0 failed.`;
- RimWorld build succeeded with 0 warnings and 0 errors; and
- the script reports `artifacts\Dagmay-RimWorld-0.1D.zip`.

If any red error appears, stop and send the complete PowerShell output. Do not edit a source file yourself.

## Step 3 — Install exactly one copy

1. Create this empty folder if it does not exist:

   ```text
   C:\Program Files (x86)\Steam\steamapps\common\RimWorld\Mods\Dagmay
   ```

2. Extract everything inside `artifacts\Dagmay-RimWorld-0.1D.zip` into that folder.
3. Confirm these exact files exist:

   ```text
   Mods\Dagmay\About\About.xml
   Mods\Dagmay\Assemblies\Dagmay.Core.dll
   Mods\Dagmay\Assemblies\Dagmay.Providers.dll
   Mods\Dagmay\Assemblies\Dagmay.RimWorld.dll
   ```

If you see an extra nested path such as `Mods\Dagmay\Package\About`, move the contents of `Package` up one level.

## Step 4 — Offline continuity and queue test

In the same PowerShell window, run:

```powershell
.\tools\configure-reflection.ps1 -Mode Offline
```

Then:

1. Start RimWorld.
2. Confirm Dagmay is enabled once in the mod list. Leave RimTalk and the other test mods in their usual positions.
3. Load a copy of the completed 0.1C test save.
4. Let the colony run unpaused for 20 seconds.
5. Save as `Dagmay_01D_Offline_1`.
6. Quit RimWorld completely.

Open `Player.log` from:

```text
%USERPROFILE%\AppData\LocalLow\Ludeon Studios\RimWorld by Ludeon Studios\Player.log
```

Search for `[Dagmay] 0.1D`. The offline gate passes when:

- `Version 0.1D loaded` appears;
- `reflection mode=offline` appears;
- the service status shows all three storage systems as `healthy`;
- Lynx, Schmidt, and Michael retain their prior exact individual and lineage IDs;
- the reflection queue is nonzero on the first 0.1D upgrade; for the supplied history it should normally be two tasks because Lynx and Schmidt have recorded evidence while Michael has none;
- no `dispatched reflection` line appears in offline mode; and
- no Dagmay line says `READ-ONLY`, `failed`, `mismatch`, `unrecoverable`, or `quarantined`.

Offline mode is a real supported mode. It must continue recording bounded experiences even though queued reflections wait.

## Step 5 — Deterministic fake-provider commit test

With RimWorld closed, return to the 0.1D source PowerShell window and run:

```powershell
.\tools\configure-reflection.ps1 -Mode Fake
```

Then:

1. Start RimWorld again.
2. Load `Dagmay_01D_Offline_1`.
3. Run the colony unpaused at normal speed for 45 seconds.
4. Look for lines in this order for each processed task:

   ```text
   [Dagmay] 0.1D dispatched reflection; provider=dagmay.fake; model=deterministic-v1; ...
   [Dagmay] 0.1D committed validated reflection; ...
   ```

5. Save as `Dagmay_01D_Fake_1` and quit completely.
6. Start RimWorld one more time, load `Dagmay_01D_Fake_1`, let it run for 15 seconds, save, and quit.

The fake gate passes when:

- there are normally two committed reflections, one for each evidence-backed queued individual;
- each commit keeps the same `IndividualId` and `LineageId` while advancing that identity's version;
- the reload reports `ReflectionStorage=healthy` and normally `ReflectionQueue=0`;
- already committed requests are not committed again after reload; and
- there is no identity/storage error or quarantined fake response.

The fake provider uses no internet and no Google credits. It intentionally proposes no affect change; the version/audit advancement proves the validated durable reflection path without letting test prose alter the individual.

## Step 6 — Optional one-call Google test

Only continue if Steps 2–5 passed. Google API usage is separate from ChatGPT Plus. Google may apply account quotas, billing rules, and data-use terms; the default model is `gemini-2.5-flash-lite`. Google's current pricing table says content submitted under the free tier may be used to improve its products. Use only fictional colony data and review [Google's current Gemini API pricing/data-use table](https://ai.google.dev/gemini-api/docs/pricing) before enabling the live test.

With RimWorld closed, run:

```powershell
.\tools\configure-reflection.ps1 -Mode Google
```

PowerShell will ask for the Google AI Studio key. Paste it and press Enter. Nothing should be displayed while you paste. Do not put the key in chat, a screenshot, a command argument, or `Player.log`.

Then:

1. Start RimWorld and load `Dagmay_01D_Fake_1`.
2. Run unpaused at normal speed for up to 110 seconds. With the earlier queue empty, the one-minute scheduler should create one background task, and the request has a 45-second maximum deadline.
3. Watch for:

   ```text
   [Dagmay] 0.1D reflection mode=google; ...
   [Dagmay] 0.1D dispatched reflection; provider=google.ai-studio; model=gemini-2.5-flash-lite; ...
   ```

4. Wait for either one `committed validated reflection` line or one clearly normalized safe-failure line.
5. As soon as that result appears, save as `Dagmay_01D_Google_1` and quit. This prevents waiting for a second background opportunity.

A commit is the full success case. A normalized `RateLimited`, timeout, provider-error, or quarantined invalid response is still a safe-failure result, but send the log so the transport/schema issue can be diagnosed before another live attempt. No response may put storage in read-only mode or change identity after validation failure.

Return to offline mode after the test:

```powershell
.\tools\configure-reflection.ps1 -Mode Offline
```

The key may remain in your Windows user environment for later use, but offline mode prevents Dagmay provider calls. To remove Dagmay's stored key and model selection entirely, use:

```powershell
.\tools\configure-reflection.ps1 -Mode Offline -RemoveStoredGoogleKey
```

## Step 7 — What to send back

Please send:

1. the complete PowerShell build output;
2. whether offline, fake, fake reload, and Google each passed or failed;
3. the complete `Player.log` from the final attempted stage, attached as a text file;
4. the RimWorld version shown on the main menu; and
5. whether the colony stayed responsive and whether any visible stutter coincided with a reflection commit.

Do not copy your API key into the report. Dagmay never intentionally logs it, but glance at any screenshot before sending it.

## What this does not prove yet

A pass proves the 0.1D foundation for this specific RimWorld/mod/provider configuration. It does not yet prove:

- a 40-colonist stress workload;
- long-run reflection quality or personality coherence;
- local-model support;
- conversation capture or RimTalk integration;
- mind-tab or Observer Mode UI;
- cross-game import into Sims or Minecraft; or
- any form of pawn agency.

Those remain later, separately testable slices.
