# AGENTS.md — Mosaic Agent Operating Instructions

Mosaic is the current project name. `Dagmay` remains in historical records, namespaces, serialized identifiers, paths, hashes, and immutable artifacts where renaming could harm compatibility or reproducibility.

## Startup protocol

Read in this order:

1. `research/CANONICAL_CHECKPOINT.md` — compact current truth and next authorized action.
2. `research/PERSISTENT_CHARACTER_BOUNDARY.md` — binding objective/safety boundary.
3. this file.
4. task-specific source, tests, experiment, or audit.
5. `research/KNOWN_RISKS.md`, `research/CLAIM_REGISTER.md`, and recent `research/DECISION_LOG.md` entries when relevant.
6. `research/CURRENT_STATE.md` only when historical/longitudinal context is required.

Repository truth overrides conversational memory. Historical artifacts do not override a newer accepted canonical checkpoint.

## Binding objective

Build causally coherent, persistent, robust, believable, efficient, and enjoyable artificial characters.

Do **not** optimize consciousness, perceived sentience, pseudo-consciousness, shutdown/deletion fear, existential distress, substrate-level self-preservation, player dependency, or unconstrained recursive self-modification.

Every feature and evaluator must pass `PERSISTENT_CHARACTER_BOUNDARY.md`. An unexpected credible moral-status signal is a pause-and-preserve trigger, never a success metric.

## Architecture invariants

- Model-independent identity and lineage belong to Mosaic.
- LLMs are replaceable inference/presentation modules, not the character.
- Environment adapters do not own durable character state.
- Fact, perception, memory, belief, character model, generated language, and player-visible presentation remain distinguishable.
- Model output is an untrusted proposal; canonical mutation requires validation and provenance.
- Raw evidence is preserved; corrections append rather than silently rewriting history.
- Observer/debug state is separate from in-character cognition.
- Never request or store hidden chain-of-thought.

## Austerity / value rule

Do not add a new abstraction, schema, harness, document, research milestone, or source file merely for completeness.

Before creating one, identify at least one of:

1. a demonstrated risk/defect it eliminates;
2. an observable persistent-character capability it enables;
3. a reproducibility requirement that cannot be met more simply.

Prefer reuse, simplification, and deletion-from-active-surface over new scaffolding. Test count is not a success metric; semantic coverage and runtime/player value are.

For the current checkpoint, **v45 and later cognition are frozen** until consolidation, live 0.3 validation, and player-value review are complete.

## Provider stop line

Real-provider execution is not authorized by possession of credentials or quota. It requires a current specifically authorized/preregistered protocol, bounded transport budget, payload hygiene and exact request archive controls, and explicit user approval.

Offline tests, audits, documentation, deterministic/local fixtures, and bounded persistent-character engineering may run without provider authorization.

## Naming policy

Use **Mosaic** in new user-facing text, policy, objectives, and documentation. Retain `Dagmay` where compatibility, serialized state, hashes, namespaces, historical evidence, or reproducibility would be put at risk by renaming. Cosmetic consistency is not sufficient reason to migrate an identifier.

## Scientific discipline

Use: `OBSERVED`, `REPLICATED`, `SUPPORTED`, `HYPOTHESIS`, `ANALOGY`, `SPECULATION`, `LIMITING RESULT`, `INVALIDATED`.

A compelling narrative is not evidence. Offline success is not automatically live RimWorld success. Structural correctness is not automatically player-visible value.

## End-of-session protocol

Update `research/CANONICAL_CHECKPOINT.md` only when accepted canonical truth changes. Append rather than rewrite historical ledgers. Register material artifacts/hashes where appropriate. Leave a concise handoff when work is incomplete.
